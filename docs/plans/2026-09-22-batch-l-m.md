## 任务分解

### T1 pcap/pcapng 解析引擎（纯函数）
- 新文件 `src/utils/ctf/pcapParse.ts`：
  - pcap 全局头（LE/BE × µs/ns 四魔数）+ 包记录遍历；pcapng SHB（字节序判定）/IDB/EPB/SPB，未知块按长度跳过。
  - 链路层：Ethernet（含 VLAN）、Linux SLL、Raw IP、Null/Loopback；网络层 IPv4（协议/分片标记）+ IPv6（基础扩展头跳转）；传输层 TCP/UDP。
  - TCP 流重组（四元组分方向、seq 归一化排序、字节上限）；HTTP 请求/响应提取（Content-Length + 简单 chunked）；复用 fileDetect 的 scanSuspiciousContent 做 flag/base64 扫描。
  - 限量常量导出：MAX_PARSE_PACKETS=20000、MAX_STREAMS=500、MAX_HTTP_OBJECTS=200、每流/每对象字节上限；损坏（incl_len 超剩余字节、块长非法）→ 停止并返回 truncated 标记 + 已解析部分，不抛异常。
- 验证：T3 单测。
- 参考：kaitai pcap/pcapng 规范（调研已确认格式公开、纯 JS 可行）。

### T2 流量分析工作区组件
- 新文件 `src/components/ctf/TrafficWorkspace.tsx`：仿 FileForensicsWorkspace 模式（pendingFile 消费 / loadFile 20MB 上限 / 概要先渲染再分析 / notifications 报错 / 组件内 style + CSS 变量主题 token，前缀 tf-）。
- 视图：概要卡（格式/字节序/链路类型/包数/时长/截断提示）→ 协议统计条 → HTTP 对象列表（点击看正文 + flag 徽标 + 复制）→ TCP 流列表（ASCII 预览 + 复制）→ 可疑内容 → 包列表预览表（前 200 条，overflow-x 横向滚动）。
- 非 pcap 文件拖入：诚实提示"不是 pcap/pcapng"，建议去杂项取证域，不崩、不清空已有结果之外的状态。

### T3 解析器单测
- 新文件 `tests/traffic-analysis.test.mjs`（file-forensics 模式，样本程序化自造）：
  - pcap-LE/µs 含 HTTP 响应藏 flag：包数、协议统计、HTTP 对象提取出 flag、TCP 流重组内容正确。
  - pcapng（SHB/IDB/EPB）同场景；BE pcap 解析正确。
  - 截断 pcap（包记录头声明长度超剩余）→ truncated=true + 已解析部分可用。
  - 伪造魔数（d4c3b2a1 后全垃圾）→ 不抛异常、返回 0 包 + 截断提示。
  - 空文件/非 pcap 文件 → 明确错误结果。
  - 包数上限：构造超限样本 → 停在 MAX_PARSE_PACKETS 并带提示。
- 期望输出：`node --test tests/traffic-analysis.test.mjs` 全绿。
