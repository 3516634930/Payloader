# Payloader-Enterprise（部署版仓库）计划

本文件是 Java 部署版仓库的筹建蓝图：定位、里程碑、边界，以及两个仓库 README 关系表的互链文案。建仓库时直接取用。

> 2026-09-20 更新：主仓库路线已精简为 16 版（v2.0.1 = CTF 增强 + GitHub 监控；为 Node→Java 迁移服务的契约冻结与迁移铺垫两版移除，企业运行时由本蓝图 v0.4 承载）。部署版的验收基线相应定为"从主仓库 v2.0.0 实际实现生成 golden fixture"。

## 仓库定位声明（可直接作为部署版 README 的开头）

> Payloader-Enterprise 是 [Payloader](主仓库地址) 的企业部署版：Java + PostgreSQL 实现，面向需要高可用读取、数据内网化、规模化分发的组织。内容的生产、投稿与审核始终在官方平台（或社区版）完成，本仓库交付的是"把内容安全装进企业内网并扛住流量"的运行时。

## 里程碑

### v0.1 — 最小部署面

- 目标：跑通"部署即服务"，公开行为与主仓库完全一致。
- 范围：公开站 + 公开 API（`/api/public-data`、health、下载等）的 Java/PG 实现；Docker Compose 单机部署。
- 验收：以主仓库 v2.0.0 实际实现为基准生成 golden fixture / 一致性测试套件，全绿后发布；主仓库的公开 API 客户端无感切换。

### v0.2 — 官方内容同步客户端

- 目标：作为同步客户端消费官方签名 Manifest。
- 范围：Manifest 格式定稿（序号、前驱 Hash、内容 Hash、信任根、有效期）；签名校验、防回放/防分叉、信任根离线轮换、本地内容永不覆盖、冲突进后台列表。
- 验收：与主仓库（官方源）完成端到端同步演练；篡改/回放用例全部拦截。

### v0.3 — MCP 服务

- 目标：提供与主仓库相同 Schema 的匿名只读 MCP（`/mcp`）。
- 范围：四个 Tool（search / get_many / get_source / get_download_url）的 Java 实现；复用主仓库的检索质量基准。
- 验收：同一 MCP Schema 一致性测试通过；检索基准达到主仓库同等阈值。

### v0.4 — 企业运行时（高可用与灾备）

- 目标：承接企业级规模能力（主仓库不做多节点/HA/灾备）。
- 范围：3 节点无状态拓扑 + HA PostgreSQL + S3/CDN；容量门禁（持续 2000 RPS、P95 ≤ 200ms、成功率 ≥ 99.9%）；正式容量（10 万条内容、2 TiB Blob）；RPO ≤ 5min / RTO ≤ 30min 恢复演练；SLO 99.95%。
- 验收：压测与灾备演练证据齐全，达标后才允许标注"生产就绪"。

## 边界声明（防功能面失控）

- 部署版**不做**内容生产管理面：投稿、审核、AI 审查、发布流程、用户注册体系永远留在主仓库/官方平台。部署版管理界面仅提供只读观察视图与同步管理。
- 若未来私有化客户要求完整管理面，走独立立项评估，不默认吸入部署版路线——这是双仓库成本失控的唯一入口，提前封死。
- 部署版不自行定义对外契约：公开 API / Manifest / MCP 行为一律以主仓库实现为基准，先在主仓库定型、部署版跟进。

## 共享契约清单（从主仓库实现沉淀，两仓库共同遵守）

1. 公开 API（含 ETag、缓存、压缩协商）
2. 内容/官方同步 Manifest（含签名与信任根规则）
3. MCP Tool Schema
4. Skills Manifest
5. 离线迁移包（数据导出/导入格式）

变更流程：主仓库先改并验证 → 沉淀为契约版本（语义化版本 + 变更记录）→ 部署版跟进 → 一致性测试双向验证。
