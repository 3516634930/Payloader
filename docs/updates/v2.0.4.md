# Payloader v2.0.4 更新计划：统一版本历史

## 目标

Payload、工具、EXP 三类内容统一到同一套"不可变版本历史"：每次修改都留痕、可对比、可恢复。

## 需求背景

v2.0.3 - v2.0.4 给 EXP 建了 Revision 机制，但 Payload 和工具还是"原地覆盖"式保存——改错了找不回，谁改的说不清。知识库的公信力要求内容演化全程可追溯。本版把三类内容统一到一套历史机制上。

## 新增/变更功能

- 三类内容统一 Revision 父链：每次新增、修改、恢复都生成完整的新版本记录，带来源与审计信息。
- 并发保护：提交时声明基于哪个旧版本（`baseRevisionId`），防止两人同时改互相覆盖。
- 管理后台提供三类内容的时间线、任意两版的字段 Diff；EXP 额外提供源码树的路径级 Diff。
- 恢复历史 = 创建一条新的"恢复"版本，旧版本永远不改写。
- 公开端只能看到当前激活版本，查不到历史，但内容 ID 和链接永远稳定。

## 预期效果

- 任何一条内容的"前世今生"都有据可查：谁在什么时候改了什么，一屏看清。
- 误改可一键恢复，且恢复动作本身也被记录。
- 公开内容链接永不失效——历史只进不改，ID 永远指向同一份内容。
