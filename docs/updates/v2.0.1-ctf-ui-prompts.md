# v2.0.1 批次提示词：CTF 工具箱全题型化 UI 重构

> 接续 `v2.0.1-toolbox-prompts.md`（批次 G/H/I 已完成验收）。本文件四个批次 J/K/L/M。
> 目标：CTF 解题 tab 从"密码题工作台"升级为"可扩展全题型框架"——题域导航 + 模块插件化，为流量分析、杂项取证、Web、逆向、Pwn、AI 题型预留架构位置。
> 执行顺序：J 最先（框架重构）→ K / L 可并行（两个新域模块）→ M 收尾。
> 每批次完成后运行门禁：`npm run verify:codec`、`npm test`、`npm run typecheck`、`npm run lint`，全绿才算完成。安全红线不变：零 eval / new Function；**零联网（CTF 解题链路不得发起任何网络请求，资产全部本地打包）**；文件解析必须限量（大小上限、步数上限、超时保护）。

**背景参考**（调研已完成，可直接采信）：
- 随波逐流 CTF 编码工具 V8.0.1（224 算法的信息架构范本）：领域制一级分类 + 类内工具平铺；「文件与图片」「文件自动探测」独立成类是 Misc 工具组织关键；全站统一输入/输出双面板。
- 流量分析可行性：pcap/pcapng 为纯字节格式（全局头 + 包记录），参照 kaitai pcap 格式规范或 npm pcap-parser 思路，纯 JS 可解 Ethernet/IP/TCP/UDP 头并重组 HTTP 对象，无需原生依赖。
- 中文密码可行性：与佛论禅/新佛曰/熊曰为"字符→生僻字表"映射编码，离线 JS 实现成熟。
- 现有代码入口：`src/components/CtfToolkit.tsx`（壳）、`src/components/CodecWorkbench.tsx`（共用工作台）、`src/utils/codec/`（引擎，22 模块）、`src/utils/codec/audience.ts`（受众分流表）。

## 批次 J：题域导航框架 + 模块插件化

**问题**：CTF 解题 tab 的 UI 是"智能识别 + 密码四分组工作台"的单一结构，没有题型维度的导航，后续加流量/杂项/Web/逆向/Pwn/AI 题型没有架构位置。

**需求**：重构 CTF 解题 tab 的信息架构为"题域导航 + 模块插件化"：顶部题域导航条切换题型域，每个题型域是一个可注册的模块，框架按激活域渲染对应工作区。现有密码/编码能力整体迁移为第一个域，行为不丢失。

**方向**：
- 定义模块注册表（如 `src/utils/ctf/modules.ts`）：`ToolkitModule` 接口声明 id/名称/图标/工作区组件/适用入口类型（文本/文件/速查），加题型 = 注册新模块，不改框架代码。
- 首批注册域：**密码与编码**（现有 `buildCtfGroups()` 工作台原样迁入）、**杂项取证 / 流量分析 / Web / 逆向 / Pwn / AI**（本批次可以是轻占位页，K/L/M 批次填充）。
- 智能识别 hero 保留全域置顶，flag 徽标逻辑复用；文件类域激活时 hero 区显示"拖入文件"第二入口（K 批次实现具体功能）。
- 题域导航用 Mantine 组件（SegmentedControl 或 Tabs），桌面横向排布，移动端（≤520px）横向可滚动，符合现有 neon 主题。
- 域切换状态保留在组件内即可（不强求 URL 持久化）；三 tab（载荷/工具命令/CTF 解题）外层结构不动。
- 回归红线：受众分流守恒校验（verify:codec 里的 67/28/59/154 记账）不得破坏；智能识别、候选评分、检测芯片行为与现状一致。

**预期效果**：CTF 解题 tab 出现清晰的题型域导航，七个域一眼可辨；密码与编码域功能与重构前完全一致；点其他域显示占位内容不报错；框架扩展一个新域只需注册一个模块对象。

**验收**：四门禁全绿 + verify:codec 受众守恒项通过；浏览器实测七域切换流畅、移动端 390px 导航可滚动不溢出、密码域操作与重构前一致（抽查智能识别 Base32 出 flag + 徽标）；console 零报错。

## 批次 K：杂项取证域 + 中文密码组

**问题**：杂项（Misc）是 CTF 出题量最大的方向之一（文件分析、图片隐写、取证杂项），现有工具箱完全没有文件类能力；中文 CTF 高频的特有密码（与佛论禅、熊曰等）也缺失。

**需求**：①杂项取证域落地为文件分析工作区：拖拽/选择文件 → 自动探测 → 按需分析，全浏览器本地处理；②密码与编码域新增"中文密码"工具组（5-8 个操作进现有引擎）。

**方向**：
- 文件自动探测引擎（参考随波逐流「文件自动探测」类的能力集，纯 JS 自实现）：文件头魔数识别（内置常见魔数表：PNG/JPG/GIF/ZIP/RAR/7z/PDF/PCAP/ELF/EXE 等）并比对扩展名一致性、信息熵计算（判定加密/压缩可能）、可打印字符串提取（strings）、可疑内容扫描（flag 格式、base64 特征、`==` 结尾、常见 CTF 关键词）、hexdump 预览。扫描结果以清单呈现，flag 命中直接亮徽标。
- 文件工具（选做，按性价比）：PNG 宽高被改修复（IHDR CRC 校验）、zip 伪加密检测与修复标志位、图片↔Base64 互转、零宽字符提取（文本已有能力接到文件场景）。
- 安全边界：文件大小上限（建议 ≤20MB，超限拒绝并提示）；解析在主线程限量或 Worker；不执行文件内容，只读字节；不上传。
- 中文密码组（进 CodecWorkbench 引擎，受众标 `ctf`，挂密码与编码域新分组"中文密码"）：与佛论禅、新佛曰（佛曰/如是我闻两种前缀）、与熊论道（熊曰）、百家姓编码、六十四卦编码、天干地支码——映射表实现，支持解码为主、编码为辅；智能识别层加入对应检测（密文含"佛曰："前缀等特征）。
- 受众表与守恒校验数字随新增操作同步更新（新增操作全部 `ctf` 或 `both`，不得进渗透视图）。

**预期效果**：拖一个 PNG/ZIP/PCAP 进杂项域，立刻看到文件类型、熵值、可读字符串、可疑内容清单，flag 藏在文件里能被扫出来；与佛论禅密文粘贴到智能识别能自动识别并解出；中文密码组在密码与编码域可见可用。

**验收**：四门禁全绿；自造测试文件（PNG 改宽高、ZIP 伪加密、藏 flag 的文本文件）逐一验证探测结论正确；与佛论禅/熊曰 round-trip 编解码正确（用公开样本对照）；文件超限拒绝路径可用；移动端拖拽退化为企业文件选择按钮仍可用。

## 批次 L：流量分析域 MVP

**问题**：流量分析（抓包题）是 CTF 取证方向核心题型，现有工具箱无法解析 pcap/pcapng，用户必须离线开 Wireshark。

**需求**：流量分析域落地为 pcap 分析工作区：上传 pcap/pcapng 文件，浏览器本地解析出包列表、协议统计和 HTTP 对象，支持从流量里提取 flag 线索。纯 JS 离线实现。

**方向**：
- pcap/pcapng 解析器（自实现或参考 npm pcap-parser / kaitai pcap 规范思路）：全局头（含字节序、纳秒/微秒精度）+ 包记录遍历；pcapng 支持多 Enhanced Packet Block。解析限量：包数上限、总字节上限、超限停止并给出已解析部分。
- 协议剥离：Ethernet → IPv4/IPv6 → TCP/UDP 头解析，产出包列表字段（序号、时间戳、源/目 IP:端口、协议、长度、摘要）。
- 分析视图（按价值排序实现）：①协议统计（TCP/UDP/ICMP/DNS/HTTP 占比条）；②TCP 流重组（按四元组+seq 排序拼接，列出流清单可逐流查看 ASCII/hex）；③HTTP 对象提取（请求行/响应识别，抽取 GET/POST 参数与响应体里的内容）；④全流量可疑内容扫描（flag 格式、base64 特征——复用 K 批次的扫描器）。
- 包列表用虚拟滚动或分页（大文件不卡死）；所有视图沿用现有双面板/表格样式与 neon 主题。
- 智能识别 hero 在流量域聚焦"文件入口"而非文本粘贴。

**预期效果**：拖一个 CTF 流量题 pcap 进来，不装 Wireshark 就能看到包列表和协议占比，HTTP 对象一键提取，藏在 HTTP 响应或 TCP 流里的 flag 被徽标标出。

**验收**：四门禁全绿；用 tcpdump/Scapy 自造含 HTTP 传输 flag 的 pcap（含 pcapng 格式各一）实测：包数正确、HTTP 对象提取出 flag、协议统计合理；超限大文件给出已解析部分与提示不崩；移动端表格横向可滚动。

## 批次 M：速查域填充 + 收尾走查

**问题**：Web/逆向/Pwn/AI 四个域如果只有空占位，用户点进去体验断裂；且批次 J/K/L 属于大改，需要独立整体验证。

**需求**：①四个域填充最小可用内容——题型速查卡（从知识库种子数据挂接该题型高频工具/命令/payload 入口，点击跳转主 tab 对应分类）+ "专属工具建设中"的诚实提示；②批次 J/K/L 交付的整体验收走查。

**方向**：
- 速查数据以静态种子文件维护（`src/utils/ctf/cheatsheets/` 按域一份），内容从项目现有 payload/工具知识库中挑选该题型最常用条目，不重复建设后端。
- 每域速查 5-10 条为宜，宁缺毋滥；条目可跳转：Web 域条目跳载荷 tab 对应分类、逆向/Pwn 条目跳工具命令 tab 对应命令。
- 走查三旅程：①密码题旅程（智能识别 → 古典 → 中文密码）；②杂项旅程（拖文件 → 探测 → flag 扫描）；③流量旅程（拖 pcap → HTTP 对象 → flag）；外加 Web/逆向/Pwn/AI 四域点击不空不报错。
- 防呆：大文件、损坏文件（截断 pcap、伪造魔数）、空输入、快速连点域导航、390px 移动端、亮暗主题。
- 问题按 P0/P1/P2 处置并记录。

**预期效果**：七个域每个都有可用内容，无空壳断裂感；三条解题旅程全程无阻塞；走查缺陷全部处置。

**验收**：四门禁复跑全绿；走查证据（截图/步骤）与 P2 记账写入交付说明；批次 J/K/L 各自验收项逐条复验通过。

## 总验收指标

- CTF 解题 tab 呈现"七域框架 + 三域可用 + 四域速查"，加新题型只需注册模块。
- 智能识别、受众分流、渗透编解码视图零回归（守恒校验钉死）。
- 新增文件/流量能力全部浏览器本地离线，零上传、零 eval、解析限量。
- 移动端全流程可用。
