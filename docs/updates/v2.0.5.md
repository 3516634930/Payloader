# Payloader v2.0.5 更新计划：待发布池与批量发布

## 目标

把"保存"和"公开"彻底分开：管理员改完内容先进待发布池，确认后一次性批量发布；出事可整批回滚或紧急下架。

## 需求背景

现在的机制是保存即公开——管理员改一半的内容会直接暴露给访客，也无法把一批相关内容作为一个整体版本管理。知识库需要像软件发布一样的节奏：准备好 → 预览 → 一次切换，并且切换出去的版本完整、一致、可回滚。

## 新增/变更功能

- 保存只产生新 Revision 和"待发布"候选，不再立即公开。
- 待发布池：支持单选、多选、跨页全选和"当前筛选结果全选"，服务端最终复核选择集。
- 批量发布：一次操作生成不可变 Release 快照（含内容与源码 Hash），公开端原子切换到新版本。
- 紧急下架：立即生成新 Release 让内容全面失效，被下架内容恢复后须重新进入待发布池。
- 回滚 = 发布一个指向旧内容的新 Release，历史 Release 永不改写。
- 公开站、客户端下载、EXP 预览/下载、Builder 全部只读"当前激活 Release"。

## 预期效果

- 管理员可以安心编辑，草稿和半成品永远不会被访客看到。
- 公开内容永远是完整一致的一批——不会出现"这篇是新版那篇还是旧版"的混合状态。
- 发布出问题能整批回滚；紧急下架一秒生效，全站所有出口同步失效。
