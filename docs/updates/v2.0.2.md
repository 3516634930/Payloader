# Payloader v2.0.2 更新计划：EXP 结构化目录

## 目标

新增 EXP（漏洞利用）内容类型，把"这个 EXP 适用于什么、使用前要满足什么条件"结构化地讲清楚。

## 需求背景

现有内容只有 Payload 和工具两类。EXP 与它们本质不同：用错对象不仅无效还可能造成破坏，使用者必须在动手前知道适用的产品、版本范围和前置条件。目前这类信息只能写在正文里，无法检索和筛选。

## 新增/变更功能

- 新增 EXP 内容类型，每个 EXP 有稳定 ID（`EXP-<ULID>`）和完整不可变版本记录。
- 结构化描述适用对象：厂商、产品、组件、别名、精确版本/版本范围/全部/未知、修复版本。
- 结构化描述前置条件：系统、架构、协议、端口、认证要求、配置、依赖。
- 结构化指纹证据：Header、页面特征、默认路径、Favicon Hash、版本正则、置信度（只做描述，不做主动扫描）。
- 管理端：新建、编辑前预览、保存并激活、隐藏与恢复。
- 公开端：EXP 列表（按产品/版本/平台/认证要求筛选）、详情页、稳定链接。

## 预期效果

- 用户找一个 EXP 时，能先看"适不适用于我的目标"，再决定用不用，而不是通读全文猜。
- 公开列表可以直接按产品、版本、平台筛选，指纹特征帮用户自己比对确认。
- 隐藏的 EXP 对外一律表现为普通 404，不泄露存在性。
- 使用方法、原作者、来源、许可证等允许留空：缺失是正常状态，不阻塞保存和发布。
