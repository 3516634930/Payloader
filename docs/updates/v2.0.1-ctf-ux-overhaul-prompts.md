# v2.0.1 CTF 工具箱体验重构 提示词（批次 U/V/W/X）

> 调研与实测依据见本文件末尾附录；执行批次前先读本头部红线。
> 上一批次文档：`v2.0.1-sbzl-parity-prompts.md`（M3/M4 已完成）。

## 全局红线（每个批次都必须遵守）

1. **零联网**：CTF 工具链运行时不发起任何网络请求；文件分析全部本地（FileReader/Uint8Array/Canvas）；指导内容只放用户手动点击的外链（`openProtectedExternalLink`）。平台管理侧（载荷库/工具命令库）不受此限，但不得与 CTF 工具链共享网络路径。
2. **安全红线不变**：零 eval / new Function；文件解析限量（现有 MAX_FILE_BYTES = 20MB、解析步数上限保持）；所有新解析器是纯函数、只读输入。
3. **交互 DNA 继承（M2/M3/M4 已定）**：顶部菜单栏 + 下拉（Mantine Menu）、点击立即执行（runAction）、【xx解密】标记法、flag 双色自动标红（FlagAutoText）、输出正则搜索 + 候选导航、输出回灌输入。
4. **受众守恒校验钉死**：改 `src/utils/codec/audience.ts` 后 `npm run verify:codec` 必须全绿；操作总数不变，仅调整归属。
5. **风格**：样式写入组件内现有 `<style>` 块或新建 `src/styles/*.css`（参照 header.css 先例）；颜色/间距用现有 CSS 变量（--neon-cyan/--border-color 等）；文案中英双语（language === 'zh' 分支）；手机端（≤680px）逐项适配。
6. 每批次完成后跑全门禁：`npm run verify:codec`（129 项基线 + 本批次新增回归）→ `npm test` → `npm run typecheck` → `npm run lint` → `npx vite build`。

## 批次 U：P0 缺陷修复 + 受众表纠偏

### 问题（调研实测确认）
1. **输出回灌污染（P0 bug）**：智能识别 hero 的「输出回灌输入」把展示文本整体回灌，内容带 `识别链路: Base64\n\n` 标头（`CtfToolkit.tsx` 的 `onUseAsInput={() => setInput(displayOutput)}`；`displayOutput = stripCandidateSection(output)`，而 `stripCandidateSection` 只剥 `=== 候选列表 ===` 之后的候选区，不剥标头）。回灌后二次识别必然失败，识别芯片消失。多层解码链第一步就断。
2. **AES 等 57 个操作对 CTF 选手隐形（P0 分类错误）**：`src/utils/codec/audience.ts` 中 59 个 `'pentest'` 独占操作里，除 `signature-nonce-helper`、`basic-auth` 外全部是 CTF 高频工具，包括全部 AES 变体（aes-gcm/cbc/ctr/ecb/cfb/ofb/cbc-raw/ctr-raw/gcm-siv/siv/kw/kwp/cmac、openssl-aes-256-cbc）、des、triple-des、blowfish、sm4、rc4、rc4-drop、rabbit、chacha20 家族（chacha20-orig/chacha20/xchacha20/chacha20-poly1305/xchacha20-poly1305/salsa20/xsalsa20/xsalsa20-poly1305）、tea/xtea/xxtea、hash、hash-identify、hmac、jwt、jwt-hmac、jwt-public、jsfuck、jsfuck-helper、aaencode、jjencode、fernet、hotp、totp、otpauth-uri、punycode、cbor、messagepack、protobuf-raw、bson、pem-block、asn1-der、jwk-jwe、ssh-public-key、querystring。CTF 选手视图里连 AES 都搜不到。
3. **识别芯片点了不执行**：hero 检测芯片走 `focusOperation`（只选中+填入+滚动，`CodecWorkbench.tsx` useImperativeHandle），而顶部菜单栏条目走 `runAction` 立即执行——同为"点击"，一个动一个不动，行为不一致。
4. **全局密钥栏重复出现**：hero 内一个（CtfHero），工作台内又一个，同屏两次，视觉噪音。
5. **「现代密码」菜单 43 项平铺无分组**：`buildCtfMenus` 的现代密码菜单把全部条目放单个 section，且解密/加密成对列出使列表翻倍；选手在长列表里滚动找 AES/RSA 很慢（随波逐流同位置是分组二级下拉）。

### 需求
- 回灌语义修复：新增"纯解码结果"提取（剥离 `识别链路: xxx` 标头行与候选区，只保留结果正文）；「输出回灌输入」只灌纯结果；hero 输入为空时直接填结果，非空时追加为新内容前先确认（或直接替换，二选一，以实现简单为准）。
- 受众表纠偏：上述 57 个操作全部 `'pentest'` → `'both'`；`signature-nonce-helper`、`basic-auth` 保持 `'pentest'`。改完 `npm run verify:codec` 的受众校验数字同步更新。
- 芯片点击 = 聚焦 + 立即执行：`focusOperation` 增加自动执行（等效菜单 runAction 的解密方向）；带 seed 时以 seed 为输入执行。
- 密钥栏去重：保留 hero 全局密钥栏；工作台内仅当当前操作声明密钥参数时，在参数区显示（现有行为），删除工作台顶部常驻重复条（如两处实现为同一组件则直接移除工作台那份，确认不破坏操作参数读取 appContext.globalSecret 的逻辑）。
- 现代密码菜单拆 sections：按「非对称与签名（RSA/Rabin/Coppersmith/PGP/ASN1 类）」「分组密码（AES/DES/SM4/Blowfish/FCrypt 类）」「流密码与序列（RC4/ChaCha/Salsa/TEA 家族/Vernam/OTP）」「散列与 JWT（hash/hmac/JWT/长度扩展）」「PRNG 与格（MT19937/LCG/LFSR）」五组；每组内条目只列解密方向，加密方向收进条目名后缀 `[加/解]` 的动作切换或保留工作台方向按钮（以改动最小为准，菜单条目数减半）。

### 方向
- 全部改动集中在：`CtfToolkit.tsx`（回灌）、`src/utils/codec/smartDecode.ts`（纯结果提取函数）、`src/utils/codec/audience.ts`（归属表）、`src/utils/codec/ctfMenus.ts`（菜单分组，若为独立文件；否则在 audience.ts 内）、`CodecWorkbench.tsx`（focusOperation 执行化、密钥栏）、`CtfHero.tsx`（密钥栏保持）。
- verify:codec 新增回归：①"57 个纠偏操作在 buildCtfGroups 可见"；②"回灌提取函数剥离标头"；③"现代密码菜单 section 数 ≥5 且无单组超 15 条"。

### 预期效果
- 选手粘贴 `U2FsdGVkX1...`（Salted openssl AES）能被识别并一键进 AES 解密；CTF 视图菜单能找到全部 AES/TEA/JWT/JSFuck。
- 多层链：Base64 → 回灌 → 再识别再解，全程无需手动清垃圾字符。
- 任何"点一下"的操作都有即时输出反馈。

### 验收
- 浏览器实测：粘贴 Base64 → 识别芯片点击后无需再点按钮直接出结果；回灌再解成功；CTF 视图菜单可见 AES-ECB/CBC、XXTEA、JWT、JSFuck、Base64；现代密码下拉五组、单项可执行。
- `npm run verify:codec` 全绿且含 3 条新回归；`npm test` 全绿；build 后 CTF 视图操作计数 ≥ 原值 + 57。
- 手机端（≤680px）菜单分组展开、密钥栏、识别芯片均可用。

## 批次 V：域首屏重构——解决"所有域都像粘贴密文"

### 问题（调研实测确认）
1. **智能识别 hero 无条件置顶七个域**：切到杂项取证/流量分析/Web/逆向，首屏依然是"粘贴密文"大输入框（还带着密码域残留内容与识别结果），文件拖放区/速查卡被挤到首屏之外。文件类题型选手第一眼看到的是无关的粘贴框——用户原话："为什么解密的是粘贴密文，其它的流量分析 逆向那些也全是粘贴密文"。
2. **misc/traffic 切域丢状态（P0）**：`ctfModules` 注册表只有 cipher `keepMounted: true`；misc/traffic 切走即卸载。实测：杂项域上传 PNG 分析出报告 → 切密码域 → 切回，文件与报告全部丢失，必须重新上传。选手分析到一半去查个编码，现场全毁。
3. **文件探测结果不驱动工具呈现**：misc 域已识别 30 种文件类型（fileDetect.ts），但无论什么文件都渲染同一套卡片（概要/修复/可疑/strings/hexdump），选手拿到 PNG 还要在一堆与己无关的卡片里找图片工具（StegOnline 模式：上传后按文件类型自动呈现适用操作）。

### 需求
- **hero 按域变形**（注册表加能力声明，不改框架判断逻辑）：
  - `cipher` 域：现状保留（完整 hero：输入+密钥栏+识别+输出）。
  - `misc` / `traffic` 域：hero 默认折叠为单行紧凑条（标题"快速文本识别" + 当前识别状态摘要 + 展开按钮）；展开后才是完整 hero；文件工作区升为该域首屏主体。域切换时折叠状态记忆（keepMounted 后自然保留）。
  - `web` / `reverse` / `pwn` / `ai` 速查域：hero 同样折叠为单行条（速查卡升首屏）；单行条上显示"需要解编码？"提示引导回 cipher 域。
- **misc/traffic `keepMounted: true`**：文件与报告跨域切换保留。注意框架层 `pendingFile` 残留重放防护逻辑（`clearPendingFile`）与 keepMounted 组合后的行为验证——keepMounted 后 onFileConsumed 清空逻辑保留，`hidden` 面板内 `scrollIntoView` 不生效的问题已有 pendingFocus 同款解法可参照。
- **按文件类型出工具**：misc 域报告头部新增"推荐工具"条：根据 `report.types` 渲染对应工具组锚点按钮（PNG → 宽高修复/位平面/色道/chunk 枚举；JPG → EOI 后附加扫描/元数据；ZIP/7z/RAR → 伪加密修复/嵌入提取；ELF/EXE/MachO → strings/常量扫描引导（指向逆向域）/熵；PCAP → 一键转流量分析域按钮；PDF/MP4/WAV 等 → strings/hexdump/熵）。无匹配类型时显示通用组。锚点滚动用现有 scrollToCard 模式，卡片未命中时 toast 说明。
- misc 域"一键全探测"雏形：文件加载完成即自动跑现有全部探测（已是如此），把报告卡按"命中优先"排序（flag 命中 > 修复工具 > 类型专属 > strings > hexdump），未命中的卡直接不渲染（现状已按条件渲染，保持）。

### 方向
- `src/utils/ctf/modules.ts`：ToolkitModule 增加 `heroMode?: 'full' | 'collapsed'`（缺省 full）；`CtfToolkit.tsx` 据此传给 CtfHero；`CtfHero.tsx` 支持 collapsed 形态（单行条 + 展开受控）。
- 推荐工具映射做成纯函数 `recommendTools(types): ToolAnchor[]`（放 fileDetect.ts 或新文件），按钮仅做锚点滚动/跨域跳转，不耦合具体工具实现——批次 W 的新工具注册进映射即可出现。
- 跨域按钮（PCAP → 流量域）复用 `setActiveModuleId` 现有通道，带 pendingFile 重定向已有魔数路由（保持，不重复造）。

### 预期效果
- 选手切到杂项取证/流量分析，首屏就是文件工作区；粘贴框收成一行随手可展开。
- 上传 PNG：首屏顶部即"PNG 工具组"锚点；上传 ELF：即"strings / 常量扫描 / 熵"组。
- 任何域切走再切回，工作现场原样保留。

### 验收
- 浏览器实测四条路径：①misc 上传 PNG → 分析 → 切 cipher 解一个 Base64 → 切回 misc 报告还在；②traffic 上传 pcap → 切 misc → 切回 pcap 报告还在；③misc 域首屏无大粘贴框（hero 折叠条高度 ≤48px）；④PNG 报告顶部出现推荐工具锚点且滚动命中。
- 回归：frontend-contract 增加"misc/traffic keepMounted"与"heroMode 缺省 full"断言。
- 全门禁绿。

## 批次 W：杂项取证纵深（对标 StegOnline/AperiSolve/随波逐流文件探测）

### 问题
misc 域现有能力 = 类型探测/熵/strings(200 条)/hexdump(512B)/PNG 宽高修复/ZIP 伪加密/零宽字符。对照开源工具与 CTF Misc 高频考点，缺：
1. 图片隐写基础件：位平面浏览（StegOnline 32 平面）、LSB 顺序提取、色道分离——StegSolve 类需求是图片题第一步。
2. 嵌入数据提取（binwalk 式）：PNG IEND 后、JPEG EOI 后尾附数据直接展示可下载；文件中段嵌入 zip/png 检出并提取（随波逐流"文件自动探测"有同类）。
3. strings 无法搜索过滤、无法导出全部；hexdump 固定 512 字节、不能跳偏移。
4. PNG 只有 IHDR：无 chunk 枚举（tEXt/zTXt/iTXt 隐藏 flag 常见位置）。

### 需求
- **位平面浏览器**：Canvas 实现 8bit × R/G/B(/A) 逐平面灰度渲染 + 平面缩略图网格；支持"从 (0,0) 按行序提取指定位平面的比特 → 组字节 → 文本预览"（LSB 提取）。通道/位选择器 + 提取按钮 + 输出走 FlagAutoText。输入超 4MP 图片提示降采样或仅分析前 N 像素（限量红线）。
- **色道分离**：R/G/B/A(/灰度) 单通道 PNG 导出下载。
- **嵌入提取**：全文件魔数扫描（复用 detectFileTypes 逐偏移滑窗，步长 1、上限扫描 8MB），命中 zip/png/jpeg/gz 在卡片列出偏移与"提取下载"按钮；PNG IEND/JPEG EOI 后有剩余字节时高亮"尾附加数据 N 字节" + hex 预览 + 下载。
- **strings 增强**：搜索框（大小写不敏感子串）、最小长度选择（4/6/8）、"复制全部"与"导出 txt"；列表虚拟化或分页（>500 条时分页，每页 200）。
- **hexdump 增强**：偏移跳转输入框、每页 512B 翻页、hex/ascii 搜索（命中滚动定位）。
- **PNG chunk 枚举**：列出全部 chunk（类型/长度/CRC 状态），tEXt/zTXt/iTXt 直接显示内容并过 FlagAutoText。
- 新工具全部注册进批次 V 的 `recommendTools` 映射（PNG/JPG/ZIP 组）。

### 方向
- 全部纯前端 Canvas/Uint8Array 实现，零依赖零网络；新增 `src/utils/ctf/imagePlanes.ts`（位平面/色道）、`src/utils/ctf/embedScan.ts`（嵌入扫描）两个纯函数模块，UI 并入 FileForensicsWorkspace 按卡片分区（复用 ff-card 模式）。
- 性能红线：位平面渲染和嵌入扫描均在前 8MB / 前 4MP 内进行；同步计算 >1s 的操作走"分析中"占位（现成 analyzing 模式）。
- 每个新能力配 verify:codec 或 node test 的纯函数回归（位平面提取、EOI 检测、chunk 枚举可用构造字节断言）。

### 预期效果
- 选手拿到一张 PNG：上传 → 推荐工具条点"位平面" → 逐平面看图 → LSB 提取直接出 flag；全程不离开浏览器。
- 拿到"图片尾部藏 zip"的题：上传 → 尾附加数据卡片直接下载。

### 验收
- 用构造样本验收：①PNG IEND 后附 `PK\x03\x04` 头 zip → 嵌入卡片检出并下载；②PNG tEXt chunk 写 flag{chunk_test} → chunk 卡片标红显示；③8×8 纯色 PNG 最低位平面嵌文本 → LSB 提取出文本。
- 全门禁绿 + 新增回归绿 + 手机端位平面网格可横向滚动。

## 批次 X：逆向 / Pwn 域 MVP（速查 → 有真工具）

### 问题
web/reverse/pwn/ai 四域现仅 54 条速查卡（web16/reverse14/pwn14/ai10），零工具能力。逆向题选手在本平台至少应该能完成"拿二进制 → strings/常量指纹 → 判断加密算法 → 回密码域解"的第一公里；Pwn 选手需要 cyclic pattern 生成/反查这类纯计算工具（Wiremask 模式，两次粘贴闭环）。反编译（Ghidra/dogbolt 类）维持指导页（L3 层），不在本批次。

### 需求
- **逆向域工作台**（替换 CheatsheetWorkspace 占位，保留速查入口在页面底部）：
  - 文件上传（复用框架 pendingFile 通道 + fileDetect ELF/PE/MachO 魔数）；20MB 上限。
  - **常量指纹扫描**（本批次核心，纯 JS）：滑窗扫描 4/8/16 字节特征，命中库：TEA/XTEA delta `0x9E3779B9`、XXTEA delta、AES S-box/逆 S-box 首 16 字节、MD5/SHA1/SHA256 初始向量、CRC32 表首项、Base64 标准/URL-safe 字母表、PNG/IEND 等结构常量、mbedtls/SQLite/UPX 版本字符串。命中即输出卡片：常量名 + 偏移 + 含义 + "下一步建议"（如"疑似 TEA 家族 → 密码域搜 TEA"）。扫描限量：前 8MB、命中去重。
  - **块级熵图**：文件按 256B 块算熵渲染条形图（Canvas div 均可），高熵区段标注偏移范围（定位加密区/资源区）。
  - strings/hexdump/推荐工具：复用批次 W 组件（不复制粘贴，抽公共模块）。
  - 速查卡保留（降到底部"题型速查"区）。
- **Pwn 域工作台**（替换占位，保留速查）：
  - **cyclic pattern 生成/反查**（Wiremask 双框联动）：输入 length 生成 de Bruijn 序列（大小写字母+数字，可调周期 3/4/8）；第二个框粘贴崩溃时寄存器/EIP/RIP 值（支持 0x 十六进制与原始子串两种输入），自动判字节序与位数输出 offset。
  - **坏字符检查**：粘贴 shellcode/payload，勾选坏字符集（\x00\x0a\x0d\x20 等），高亮命中字节。
  - **格式化字符串 offset 计算**：输入 `AAAA%p%p%p...` 泄漏串中的目标值，算第几个参数（纯计算）。
- **web / ai 域**：保持速查占位（本批次不做，如实显示"建设中"），但批次 V 的 hero 折叠已覆盖其首屏问题。

### 方向
- 新文件：`src/utils/ctf/constFingerprints.ts`（常量库+扫描纯函数）、`src/utils/ctf/cyclic.ts`（de Bruijn 生成/反查纯函数）、`src/components/ctf/ReverseWorkspace.tsx`、`src/components/ctf/PwnWorkspace.tsx`；`modules.ts` 换注册并将 entryKinds 改 `['file','cheatsheet']`（reverse）/`['text','cheatsheet']`（pwn）。
- pendingFile 路由扩展：ELF/PE/MachO 魔数 → 逆向域（现在只有 pcap 路由）。保持"当前域接受文件则留在当前域"优先级。
- 常量库数据以`hex 字面量数组`硬编码（零联网、零依赖）；扫描函数 5 个用例级 node 回归（构造含 TEA delta 的假 ELF）。

### 预期效果
