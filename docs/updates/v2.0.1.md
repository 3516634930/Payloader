# Payloader v2.0.1 更新计划：CTF 解题能力增强 + GitHub 仓库监控 + CTF 解题工具箱

> **进展（2026-09-20，开工首日）**：
> - **安全**：npm audit 11 个漏洞清零（sm-crypto critical 升级 0.5.7，项目只用 sm3/sm4 无实际暴露）；安全审查完成——P0 零个，两个 P1 已修复（登录 scrypt 并发闸防线程池耗尽、构建新鲜度检查改 stale-while-revalidate 防未认证放大 DoS），177 测试全过。
> - **前端优化**：Mantine 9.6.1 已引入（Provider + neon 色板主题映射 + 亮暗切换桥接 + postcss，性能门禁 439ms/353ms 达标）；导航树叶子上限 15 自动分组为二级菜单（SQL/NoSQL 注入 80 个平铺条目 → 13 个语义分组）；Payload/工具详情页从卡片堆改为分隔线紧凑列表。
> - **CTF 修正**：调研确认旧实验线 37 个提交的能力已被 v2.0.0 100% 吸收（12 层链式解码、Vigenère/替换密码 hill-climbing、RSA 攻击套件均在），无需重建；本版 CTF 增强改为补真实缺口（JSFuck/aaencode 还原、冷门 Base 变体、NTLM 计算、Magic 式多候选展示、两处乱码正则修复）。

## 目标

两个工作块：①强化 CTF 场景的解题能力，让"拿到密文/工具输出 → 拿到 flag"的链路在产品内一条龙完成；②把 GitHub 远端仓库更新监控从"只看 Payloader 自身"扩展到"任意内容源仓库"，管理员在一个页面掌握所有知识源的动态。

> **进展（2026-09-21，增补）**：批次 A-F（智能解码评分重排、编码新增、混淆 JS 还原、古典破译、RSA 攻击、收尾）已实现并验收通过：gap-test 31/47 → 42/47（有效分 42/42）、verify:codec 123/123、test 177/177 全绿。剩余批次 E 残余（PGP 报文解析、padding-oracle 演示器，素材已归档）随后续批次安排。

## 需求背景

**CTF 线**：Payloader 的核心用户是安全从业者，CTF 是高频场景。此前在旧代码基线上验证过一整套解码增强（多层编码链式解码、古典密码自动识别、噪声剥离、输入格式预处理，累计 37 个实验提交），实战效果已确认。因本地历史与远端无关，main 已重置回 v2.0.0 基线，这批成果需要在新代码结构上重建并继续增强——实验分支 `local-ctf-experiment` 与本地脚本/数据素材完整保留，重建不是从零猜。

**监控线**：自托管用户需要感知两类更新。Payloader 自身的新版本——v2.0.0 已交付"系统更新"检查器（稳定通道：GitHub Release/tag/package.json 三级回退 + semver 对比；源码通道：默认分支 commit 对比；6 小时轮询、ETag 条件请求、管理端"系统更新"页面），重置基线后即已可用，本版只需验证与打磨。外部内容源仓库——CTF payload 库、知识库源仓库的更新目前完全看不到，这是本版的核心增量。

## 新增/变更功能

### CTF 解题能力增强

- 智能解码工作台：粘贴任意可疑字符串，自动识别编码/密码类型并尝试**多层链式解码**（Base 系列/Hex/Octal/URL/ROT 系/A1Z26 等），展示解码链。
- 古典密码自动识别：凯撒、Atbash、维吉尼亚（含 hill-climbing 破解）、仿射、替换密码的自动检测与求解，按字母比例与可读性评分排序候选。
- 噪声剥离：从 CTF 平台与工具输出中自动剥离提示词、装饰前缀（`[+]`/`[!]` 等）与无关字段，提取有效密文。
- 输入预处理：hexdump/xxd 地址列剥离、Python 字节数组（`b'\x..'`）与十六进制数组自动规范化。
- CTF 平台适配：主流平台 flag 前缀与格式识别，作为解码正确性的验证信号。
- 内容库扩充：补充 CTF 方向的 payload 条目与工具命令。

### CTF 解题工具箱（信息架构重组）

- 问题现状：编解码工作台 154 个操作混装"渗透 payload 处理"与"CTF 解题"两类场景，找工具靠翻，不符合真实使用习惯——渗透时翻出一堆 CTF 杂项编码，解题时又被工程向操作淹没。
- 新增第三个顶栏 tab「CTF 解题」（载荷 / 工具命令旁边），切换到独立的 CTF 解题工具箱视图。
- 操作按受众分流，同一解码引擎两套视图：`pentest`（渗透专属）、`ctf`（解题专属）、`both`（基础操作两边共享）。
  - 编解码 tab 瘦身为真实渗透场景：URL/HTML/XML 实体、Unicode/UTF-7/JS 转义、Base64/64url/32、Hex/Binary/Octal、GZip/Deflate/Data URL、JWT/Basic Auth/Query、哈希与 HMAC、AES/DES/RC4/ChaCha 等对称算法、XOR 裸运算、JSFuck/aaencode/jjencode 混淆（payload 混淆绕过手法）、CBOR/MessagePack/Protobuf/BSON 协议解析、PEM/ASN.1/JWK/SSH、Punycode、时间戳、Fernet/HOTP/TOTP、哈希识别等。
  - CTF 解题 tab 收编解题向操作（约 65 个）：智能多层解码（置顶入口）、古典密码全套（维吉尼亚/替换/仿射/栅栏/Playfair/Enigma 等 24 个）、ROT/XOR 破译（bruteforce/known-plaintext/magic）、冷门 Base 变体（z-base-32/45/91/32768/Bech32/Base58Check）、取证与杂项编码（UUencode/XXencode/yEnc/Morse/Baudot/BCD/格雷码/DNA/GSM7/零宽/brainfuck/ook/键盘偏移/反转）、现代密码攻击助手（RSA 族/Coppersmith/离散对数/MT19937/LCG/LFSR/长度扩展/PGP/padding-oracle/BIP39）。
- 解题特色：智能解码置顶、flag 格式识别徽标（作为解码正确性信号）、候选评分排序沿用批次 A 成果、操作分组二级菜单沿用导航分组规则。
- 纯信息架构重组，不新增算法：解码引擎与操作实现物理不变，仅拆分共享模块 + 视图过滤，回归测试必须零回归。

### CTF 解题工具箱全题型化 UI 重构（2026-09-22 增补）

- 问题现状：CTF 解题 tab 当前只有密码/编码能力（智能识别 + 四分组工作台），信息架构没有为"多题型"留位置。CTF 题型远不止密码——流量分析、杂项取证、Web、Pwn、逆向、AI 题各有完全不同的工具形态（文本解码器 vs 文件分析器 vs 包解析器 vs 速查表），硬塞进现有工作台会把范式撑破。
- 调研结论（随波逐流 CTF 编码工具 V8.0.1，224 算法仍好用的原因）：①领域制一级分类，类内工具平铺，不搞深层树；②「文件与图片」「文件自动探测」独立成类——文件类工具统一拖拽工作区，文件版的智能识别（文件头/可疑字符串/exif 一键扫）是 Misc 方向的组织核心；③全站统一"输入→输出"双面板交互；④中文特有密码（与佛论禅/熊曰/百家姓/六十四卦）独立大类。
- 新信息架构：**题域导航 + 模块插件化**。
  - 顶部题域导航（Mantine SegmentedControl，移动端横向滚动）：密码与编码 / 杂项取证 / 流量分析 / Web / 逆向 / Pwn / AI。
  - 模块注册表（`ToolkitModule` 插件接口）：每个题型域一个模块，声明 id/名称/图标/工作区组件，框架按激活域路由渲染；未来加题型 = 注册新模块，不改框架。
  - 智能识别 hero 保留为全域置顶入口（文本密文仍是最高频入口），flag 徽标全域复用；文件域另有"拖入文件"入口。
  - 域内容规划：密码与编码 = 现有能力原样迁移 + 新增中文密码组；杂项取证 = 文件拖拽 + 自动探测（魔数/熵/strings/可疑特征扫描）+ 图片基础工具 + 文本清洗；流量分析 = pcap/pcapng 上传解析 + 包列表/协议统计/HTTP 对象提取（纯 JS，格式规范公开，离线可行，已调研 npm pcap-parser 与 kaitai pcap 规范）；Web/逆向/Pwn/AI = 本轮速查表占位（挂接知识库相关条目），后续版本填充专属工具。
- 纯前端离线实现，不引入原生依赖；文件分析不上传服务器，全部浏览器本地处理。

### GitHub 仓库更新监控

- 内容源订阅：管理端可添加任意 GitHub 仓库为监控目标，跟踪其 Release 与默认分支 commit 更新；预置一批精选 CTF 资源仓库。
- 检查引擎：复用 v2.0.0 version-checker 的安全骨架并扩展为多目标——固定 `github.com` host（配置只能给 owner/repo，不能改网络目的地）、10 秒超时、512 KiB 响应上限、ETag 条件请求（304 响应不消耗 API 配额）、可选 token 仅存服务器内存、全部端点走管理端鉴权。
- Atom feed 通道：对订阅仓库补充 `releases.atom` / `commits.atom` 抓取，不占 REST API 配额，适合监控大量第三方仓库。
- 更新中心增强："系统更新"页升级为两部分——Payloader 自身状态（已有）+ 订阅仓库列表（逐仓库最新版本/最新 commit/更新时间/手动检查）。
- 明确不做 webhook：接收 webhook 需要公网可达端点，且要求对目标仓库有管理权限——自托管软件监控任意第三方仓库的场景下两者都不成立，轮询是正确路线。

## 预期效果

- CTF 用户：粘贴密文或工具输出 → 自动识别 + 链式解码 + 噪声剥离 → 直接给出 flag 候选；主流编码/古典密码场景不再需要手动串多个外部工具。
- 渗透用户：编解码 tab 只剩真实工作会碰到的操作（payload 编码、协议令牌、对称加密、混淆绕过），找工具一步到位，不再被 CTF 杂项干扰。
- 双场景用户：顶部「载荷 / 工具命令 / CTF 解题」三个 tab 一目了然，CTF 解题视图按"智能识别 → 古典密码 → 现代密码 → 编码杂项"分组，一看就知道按什么流程解题。
- 管理员：打开"系统更新"同时看到 Payloader 自身版本状态和全部订阅仓库的最新动态，知识源更新不再靠刷 GitHub。
- 安全边界不放松：所有 GitHub 访问沿用 v2.0.0 已验证的固定目标、超时限量、凭据隔离与鉴权设计，新增的多目标监控不引入新的攻击面。
