# Payloader v2.0.9 更新计划：Reviewer 人工审核工作流

## 目标

为审核员建立正式的人工审核工作流：统一队列、三种处置动作、并发安全的最终决定，让投稿能够被高效、公正地处理。

## 需求背景

v2.0.9 打开了投稿入口，但处理投稿还只有管理员的最小闭环。要承接社区规模的内容贡献，需要多个审核员并行工作，且每个人的决定都要留痕、防冲突、可追溯。

## 新增/变更功能

- 按类型授权：管理员授予 Payload/工具/EXP 的审核权限，审核员只看到获权类型的队列；管理员可处理全部。
- 统一审核队列，三种动作：原样通过、退回修改（必须给结构化意见，可定位到字段或源码行）、编辑后通过。
- 编辑后通过：生成派生版本 + 服务端 Diff + 修改理由，计入贡献关系，绝不覆盖原候选。
- EXP 审核安全：修改源码重新过全部安全校验并生成新源码树；界面只显示转义纯文本，不执行源码。
- 陈旧基线处理：投稿基于的旧版本与新版本有差异时，审核员必须看三方 Diff 并确认完整替换后才能通过；多个并行候选不自动合并，后批准者取代先批准者，历史全保留。
- 并发安全：多审核员可同时只读浏览，最终决定用候选 Hash + 短时令牌做原子竞争，最多一个生效。
- 不可变审核记录：每次决定都留档；投稿人只看到最终意见或安全摘要，看不到内部审核资料。

## 预期效果

- 多个审核员可以放心并行工作，不会互相覆盖或重复决定。
- 每条公开内容的"谁审核的、怎么改的、为什么这么定"全部可追溯。
- 投稿人得到明确的、结构化的审核反馈，形成高质量的贡献循环。
