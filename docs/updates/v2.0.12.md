# Payloader v2.0.12 更新计划：官方内容安全同步

## 目标

让自托管实例能安全地同步官方平台的内容更新：签名验证防伪造，本地内容永不被覆盖。

## 需求背景

自托管用户希望享受官方持续更新的内容库，但"从远程拉数据"天然有信任问题：内容被篡改怎么办？回放旧数据怎么办？本地管理员自己改过的内容被远程覆盖怎么办？本版用签名 Manifest + 本地优先策略解决。

## 新增/变更功能

- 签名同步流：官方平台签发带序号、前驱 Hash、内容 Hash、有效期的 Manifest；自托管实例固定信任根（只能管理员离线轮换），整批校验签名、防回放、防分叉，任何一项不对就整批拒绝。
- 同步管理：管理员可开关同步、手动检查更新，能预览官方新增/更新了什么。
- 本地优先：官方新增可直接导入；官方更新只在本地从未改过时才导入——本地修改、本地新增、用户投稿永远不被覆盖，冲突进后台列表由管理员裁决。
- 导入只进待发布池，不自动公开；官方下架不自动同步，由本地管理员自行决定。
- 透明度边界：来源关系只用于后台防覆盖判断，公开端不显示"官方/本地/社区"标签。
- 数据互通格式：定义社区版（SQLite）与部署版（PostgreSQL）之间的规范化全量导出/导入格式，用户可以在两个版本之间带着数据迁移（部署版蓝图 v0.2 依赖此格式）。
- 双仓库互通：Manifest 格式、签名算法与信任根规则对部署版（Payloader-Enterprise）同等生效——它是另一类同步客户端，消费同一契约（见 [deployment-repo-plan.md](deployment-repo-plan.md)）。

## 预期效果

- 自托管实例"一键跟随官方更新"，同时保持对本地内容的完全主权。
- 传输链路上任何篡改、回放、伪造都会被签名校验拦下。
- 管理员始终是内容的最终决定者：同步进来的只是候选，公开与否、覆盖与否都由人拍板。
- 本版签发的 Manifest 成为**双仓库数据桥**：社区版与部署版消费同一套签名同步流，一处签发、两类客户端。
