# Payloader v2.0.6 更新计划：用户与权限核心

## 目标

引入用户体系和三种角色（投稿者 CONTRIBUTOR、审核员 REVIEWER、管理员 ADMIN），建立安全可靠的登录与账号管理基础。

## 需求背景

v2.0.9 起要开放用户投稿和审核协作，但目前系统只有一个共享管理口令，没有"用户"概念。必须先把身份、角色、会话的地基打牢，且管理员的初始化和恢复路径必须绝对安全。

## 新增/变更功能

- 三种角色：投稿者、审核员、管理员；系统永远只有一个不可转让、不可降级的管理员。
- 安全初始化：全新实例用一次性 bootstrap 账号进入"仅设置"会话，设置正式管理员邮箱和新密码后 bootstrap 永久失效；升级实例的管理员迁移到邮箱登录同样走安全流程。
- 邮箱即登录标识：大小写无关、全局唯一，公开昵称与邮箱彻底分离。
- 用户管理：管理员可创建、禁用用户，授予/撤销审核员，改邮箱、轮换临时密码、踢会话；用户记录不物理删除。
- 临时密码：短时、一次性、登录后强制改密，改密即撤销所有旧会话。
- 会话安全：服务端只存令牌 Hash，HttpOnly/Secure/SameSite Cookie；权限变化立即撤销相关会话；备份恢复后登录态全部清空。

## 预期效果

- 系统从"单管理员共享口令"演进为"可管理的多用户体系"，为投稿审核铺路。
- 管理员账号永远不会被锁死在门外：初始化、迁移、恢复路径全部明确且防抢占。
- 邮箱、密码 Hash、内部 ID 等敏感信息永不出现在公开接口；会话不可跨实例复用。
